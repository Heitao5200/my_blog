## Task00


### F01 [Task00] 成为智能体系统的“构建者”相比于“使用者”的核心转变是什么？

<details>

转变在于从仅调用 API 转向深入理解核心架构、设计范式，并能穿透框架表象从第一性原理出发构建应用。例如：使用者只会用网页版 ChatGPT，而构建者能编写代码让模型自主调用搜索工具解决问题。教材章节：前言

</details>


### F02 [Task00] 为什么建议为课程建立独立的Python环境？

<details>
<summary>回忆后翻看答案</summary>

隔离依赖，减少与其他项目互相影响，并便于记录和复现环境。遇到缺包先确认解释器与安装依赖使用的是同一个环境。教材：Extra07第3—4节。

</details>


### F03 [Task00] 为什么在配置大模型 API 时推荐使用 .env 文件而非直接硬编码？

<details>
<summary>回忆后翻看答案</summary>

配置与代码分离有利于切换环境和避免把密钥直接写入源码，但.env本身不是加密保险箱，仍应排除Git提交。变量名及加载方式按当前脚本核对，例如Extra07使用OPENAI_API_KEY等变量。教材：Extra07-4.3。

</details>


### F04 [Task00] 如何验证 Tavily Search API 的连通性是否正常？

<details>
<summary>回忆后翻看答案</summary>

通过运行简单的 Python 脚本调用 `TavilyClient.search` 方法并观察是否返回搜索结果来验证。例如：若 API Key 错误或额度用尽，程序会抛出异常而非输出检索到的网页摘要。教材章节：Extra07-6.1

</details>


### F05 [Task00] FirstAgentTest.py 运行成功后的“循环”输出代表了什么？

<details>
<summary>回忆后翻看答案</summary>

它代表了智能体处于 ReAct 模式下的“思考-行动-观察”循环，显示了 Agent 逐步拆解任务的过程。例如：循环 1 可能在查询天气，循环 2 则基于天气结果推荐景点。教材章节：Extra07-6.3

</details>


## Task01


### F06 [Task01] ReAct (Reasoning and Acting) 范式的核心协同效应是什么？

<details>
<summary>回忆后翻看答案</summary>

推理引导下一步行动，工具返回的观察为后续判断提供外部依据。例如不知道某条资料时先搜索，再检查来源。工具输出也可能错误，ReAct并不保证答案正确。教材：4.2.1。

</details>


### F07 [Task01] 在定义智能体工具（Tools）时，为什么“描述（Description）”字段至关重要？

<details>
<summary>回忆后翻看答案</summary>

大语言模型主要依靠这段自然语言描述来判断何时以及如何调用该工具，描述模糊会导致调用失败。例如：计算器工具应描述为“用于处理复杂的数学运算”，否则模型可能尝试自己口算。教材章节：4.2.2

</details>


### F08 [Task01] Plan-and-Solve 范式与 ReAct 范式在执行逻辑上的主要区别是什么？

<details>
<summary>回忆后翻看答案</summary>

教程中的Plan-and-Solve先生成步骤，再由执行器逐步执行；ReAct根据每次观察决定后续行动。例如前者先列出多步计算计划，后者可能根据工具返回调整下一步。计划仍可能错误，需要验证。教材：4.3.1。

</details>


### F09 [Task01] Reflection（反思）机制如何驱动智能体提升输出质量？

<details>
<summary>回忆后翻看答案</summary>

通过引入“执行-反思-优化”循环，由“评审员”角色审查初稿并提供改进建议，促使模型迭代修正。例如：第一轮生成的代码虽然正确但效率低，反思后第二轮会改用更高效的算法。教材章节：4.4.1

</details>


### F10 [Task01] 在实现 ReAct 循环时设置 `max_steps` 的目的是什么？

<details>
<summary>回忆后翻看答案</summary>

它作为安全阀防止智能体在遇到解析错误或工具无法返回结果时陷入死循环，从而耗尽 API 额度。例如：若 Agent 持续生成无效 Action，达到 5 步后系统会自动强制终止。教材章节：4.2.3

</details>


## Task02


### F11 [Task02] HelloAgents 框架中“万物皆为工具”的设计理念是指什么？

<details>
<summary>回忆后翻看答案</summary>

为了降低抽象复杂度，将记忆、RAG、协议等模块统一抽象为工具，让学习者回归“智能体调用工具”的核心逻辑。例如：Memory 不再是复杂的独立组件，而是一个可以通过 `memory_tool.run()` 操作的工具。教材章节：7.1.2

</details>


### F12 [Task02] HelloAgentsLLM 的“自动检测机制”优先级逻辑是怎样的？

<details>
<summary>回忆后翻看答案</summary>

优先检查特定服务商的环境变量（如 `ZHIPU_API_KEY`），其次解析 `base_url` 的特征字符，最后分析 Key 格式。例如：若 URL 包含 `localhost:11434`，则自动推断 Provider 为 Ollama。教材章节：7.2.3

</details>


### F13 [Task02] Agent 抽象基类中使用 `@abstractmethod` 装饰 `run` 方法的作用是什么？

<details>
<summary>回忆后翻看答案</summary>

它强制所有具体的智能体子类（如 ReActAgent）必须实现该方法，确保了整个框架具有统一的执行入口。例如：未实现 `run` 的子类在实例化时会报错，从而规范了开发标准。教材章节：7.3.3

</details>


### F14 [Task02] ToolRegistry（工具注册表）在框架中承担什么角色？

<details>
<summary>回忆后翻看答案</summary>

它作为管理中枢，负责工具的注册、发现和执行，并将工具的自然语言描述传递给 Agent。例如：Agent 调用 `search` 时，由注册表根据名称找到对应函数并执行。教材章节：7.5.1

</details>


### F15 [Task02] 教程的文本式ReActAgent为何约定Thought与Action格式？

<details>
<summary>回忆后翻看答案</summary>

约定格式便于解析器提取动作和参数；格式错误可能触发重试或步数限制。这是示例实现的协议，不是所有Agent必须采用的格式，也不能据此完整观察模型内部计算。教材：7.4.2。

</details>


## Task03


### F16 [Task03] 智能体记忆系统（Memory）与 SimpleAgent 的 `_history` 列表有何本质区别？

<details>
<summary>回忆后翻看答案</summary>

简单内存历史通常随进程结束丢失；配置了持久化存储的Memory可以跨会话保存和检索信息。Memory能否跨会话工作取决于具体存储配置，不应只凭类名判断。教材：8.1—8.2。

</details>


### F17 [Task03] RAG (检索增强生成) 技术解决大模型哪方面的核心局限？

<details>
<summary>回忆后翻看答案</summary>

RAG让模型在回答前获取外部或私有资料，缓解知识时效性和访问范围的局限。例如检索课程新文档再回答；最终质量仍依赖资料、检索和生成，不保证消除幻觉。教材：8.1、8.3。

</details>


### F18 [Task03] 将 Memory 封装为 MemoryTool 的主要好处是什么？

<details>
<summary>回忆后翻看答案</summary>

符合框架统一接口的设计，使 Agent 无需理解记忆的具体存储逻辑，只需像调用搜索一样调用记忆。例如：Agent 在思考时决定“存入当前用户信息”，即执行 `MemoryTool` 的 add 操作。教材章节：8.1

</details>


### F19 [Task03] RAG 系统中向量检索（Vector Retrieval）的作用是什么？

<details>
<summary>回忆后翻看答案</summary>

向量检索按语义相似性召回候选片段，供后续筛选与生成使用。相似度高不代表一定相关或正确，要检查片段是否真正支持回答。教材：8.3。

</details>


### F20 [Task03] 在构建 Q&A 助手时，如何验证 RAGTool 是否生效？

<details>
<summary>回忆后翻看答案</summary>

检查工具调用日志、检索片段以及它们是否实际进入模型上下文，再核对答案依据。开关RAG的对照实验可提供补充证据，但单次答案变化不能单独证明检索生效。教材：8.4；补充验证建议。

</details>


## Task04


### F21 [Task04] 什么是上下文工程（Context Engineering）？

<details>
<summary>回忆后翻看答案</summary>

它是一套系统化方法，用于在模型调用前拼装、优化输入上下文，以提升 Agent 的正确性和效率。例如：不仅传入历史对话，还通过相关性评分挑选出最有用的记忆和知识。教材章节：9.1

</details>


### F22 [Task04] ContextBuilder 在处理超限上下文时的“预算守护”策略是什么？

<details>
<summary>回忆后翻看答案</summary>

它根据 Token 限制对信息进行优先级排序，在预算内保留高价值信息，对低价值部分进行截断或压缩。例如：优先保留最新的对话和高相关性的 RAG 片段，剔除较早的无关信息。教材章节：9.3.1

</details>


### F23 [Task04] NoteTool（结构化笔记工具）与 MemoryTool 的使用场景有何不同？

<details>
<summary>回忆后翻看答案</summary>

Memory支持多种记忆类型和检索；NoteTool侧重可显式维护的结构化任务笔记，如进度、结论和阻塞点，两者能力可重叠。长程任务可用NoteTool保存下一步，配合Memory检索背景。教材：8.2、9.4。

</details>


### F24 [Task04] ContextBuilder 生成的上下文模板通常包含哪些关键分区？

<details>
<summary>回忆后翻看答案</summary>

通常包括 Role（角色）、Task（当前任务）、State（当前状态）、Evidence（知识证据）和 Output（输出要求）。例如：这种分区组织有助于模型清晰区分背景知识与当前指令，减少逻辑混淆。教材章节：9.3.1

</details>


### F25 [Task04] 如何通过 ContextAwareAgent 验证上下文优化的效果？

<details>
<summary>回忆后翻看答案</summary>

对比直接对话与启用 ContextBuilder 后的回答准确度，或打印 `optimized_context` 检查信息组织形式。例如：优化后的上下文会把复杂的知识分块呈现，使模型更容易捕捉关键细节。教材章节：9.3.1

</details>


## Task05


### F26 [Task05] 通信协议（如 MCP）解决的最核心问题是什么？

<details>
<summary>回忆后翻看答案</summary>

协议统一客户端与服务端的交互约定，减少重复编写专用集成逻辑。连接已有服务仍可能需要安装、认证、权限和配置，并非任何工具都能无条件接入。教材：10.1.1。

</details>


### F27 [Task05] MCP (Model Context Protocol) 的设计哲学中“上下文共享”指的是什么？

<details>
<summary>回忆后翻看答案</summary>

MCP可通过资源、工具等机制向客户端提供背景信息与功能。例如服务端可暴露文档内容供模型参考；文件引用关系等额外信息是否提供取决于服务实现，不是每次调用自动附带。教材：10.1—10.2。

</details>


### F28 [Task05] MCP 服务器（MCP Server）在通信架构中扮演什么角色？

<details>
<summary>回忆后翻看答案</summary>

它作为具体的服务提供方，运行特定的业务逻辑或连接私有数据，并暴露标准化的工具接口给客户端。例如：一个本地数据库 MCP 服务器负责执行 SQL 并返回查询结果给 Agent 客户端。教材章节：10.1.3

</details>


### F29 [Task05] HelloAgents 中 MCPTool 的“自动展开机制”有什么优势？

<details>
<summary>回忆后翻看答案</summary>

它能将 MCP 服务器提供的多个工具自动注册为 Agent 的独立可用工具，无需开发者逐一手动添加。例如：一个 `calculator` MCP 服务包含加减乘除 4 个接口，注册后 Agent 会自动拥有 4 个对应工具。教材章节：10.2.4

</details>


### F30 [Task05] 开发者在什么场景下应该考虑构建自定义 MCP 服务器？

<details>
<summary>回忆后翻看答案</summary>

当需要封装企业特有业务逻辑、访问私有数据库或连接特定硬件设备且社区无现成服务时。例如：公司内部的财务报表查询系统可以封装为 MCP 服务器供 AI 助手安全调用。教材章节：10.5.1

</details>


## Task06


### F31 [Task06] 深度研究助手（Deep Research Agent）中“TODO 驱动”流程包含哪三个核心要素？

<details>
<summary>回忆后翻看答案</summary>

包含智能规划器（生成子任务）、任务执行器（执行搜索与总结）和报告生成器（整合最终结果）。例如：用户问“什么是 Agent”，规划器先列出定义、架构、应用三个子任务，再按序执行。教材章节：14.2.1

</details>


### F32 [Task06] 在 PlanningService 中，如何处理 Agent 返回的非结构化 JSON 响应？

<details>
<summary>回忆后翻看答案</summary>

教材示例先提取JSON片段，再解析并验证字段，以处理前后附带说明的情况。正则提取有局限，仍需处理嵌套结构、无效JSON和缺失字段。教材：14.5.1。

</details>


### F33 [Task06] ToolAwareSimpleAgent 相比基础 SimpleAgent 新增了什么关键功能？

<details>
<summary>回忆后翻看答案</summary>

它增加了一个工具调用监听器（Listener），允许在每次工具执行时触发回调函数以记录日志或更新界面。例如：在深度研究中，通过此功能可以实时向前端推送“Agent 正在使用 Google 搜索”的提示。教材章节：14.3.2

</details>


### F34 [Task06] 深度研究助手采用的“顺序协作模式”有什么特点？

<details>
<summary>回忆后翻看答案</summary>

教材中的主要工作流先规划，再执行子任务，最后汇总报告，后续阶段依赖前面产生的信息。这不意味着所有多Agent系统都必须全局串行，独立任务能否并行取决于设计。教材：14.3.3。

</details>


### F35 [Task06] 如何评估深度研究助手中规划器生成的任务质量？

<details>
<summary>回忆后翻看答案</summary>

检查子任务是否覆盖问题、避免重复、可执行，搜索查询是否明确。不要只用任务数量判断质量；例如三个子任务都重复同一问题就应修改规划。教材：14.5.1。

</details>


## Task07


### F36 [Task07] 毕业设计要求项目以开源形式提交，其中 `requirements.txt` 的作用是什么？

<details>
<summary>回忆后翻看答案</summary>

它详细列出了运行该项目所需的所有第三方依赖包及其版本，确保其他开发者能复现运行环境。例如：若漏掉 `openai` 或 `tavily-python`，其他人运行代码时会报 `ModuleNotFoundError`。教材章节：16.1.2

</details>


### F37 [Task07] 在 GitHub 上提交毕业设计的 Pull Request (PR) 流程通常包含哪些步骤？

<details>
<summary>回忆后翻看答案</summary>

Fork 仓库、在自己的分支开发、提交代码、发起 PR 并等待社区 Review 通过后合并。例如：提交后若导师建议优化 Prompt，应在同一 PR 中追加提交，直到满足合并要求。教材章节：16.1.2

</details>


### F38 [Task07] 毕业设计文档（README.md）中为什么需要包含清晰的项目描述和运行指南？

<details>
<summary>回忆后翻看答案</summary>

它帮助评审者快速了解项目的核心功能、技术亮点以及如何正确配置 API Key 启动 Demo。例如：一份好的 README 会包含一张运行效果图和简单的 3 步启动教程。教材章节：16.1.2

</details>


### F39 [Task07] 毕业设计中“多智能体协作”相比单体 Agent 的核心优势体现在哪？

<details>
<summary>回忆后翻看答案</summary>

合理分工可让职责和中间结果更清楚，但也会增加通信、协调和错误传播成本。例如研究与核验可分开处理，但应与单Agent基线比较，不能认定Agent越多越好。教材：16.1、13.3；补充评估建议。

</details>


### F40 [Task07] 完成 Hello-Agents 教程并获得“毕业”后，进一步探索的方向有哪些？

包括深入研究前沿论文、将 RAG 应用于多模态场景、优化 Agent 性能、以及积极参与开源社区贡献。例如：尝试为框架添加新的插件系统或支持更复杂的长程规划算法。教材章节：16.7

</details>
